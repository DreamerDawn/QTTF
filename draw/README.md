# 乒乓球比赛抽签器 · Table Tennis Draw

单打 / 双打比赛的抽签工具：参赛单元录入、种子与分档、小组赛分组、淘汰赛签表，
以及 **A4 横向树状签表**的 PDF / PNG / Excel 导出。

**纯静态 · 无后端 · 无第三方库 · 可直接部署 GitHub Pages。**

---

## 部署

把整个 `draw/` 目录（或其中的 `index.html` + `css/` + `js/`）放到仓库根目录或 `docs/`：

1. 复制 `index.html`、`css/`、`js/`（`tests/` 可选，不影响运行）
2. 仓库 **Settings → Pages** → 分支 `main`、目录 `/`（或 `/docs`）
3. 访问 `https://<用户名>.github.io/<仓库名>/`

本地直接双击 `index.html` 即可（全部是经典 `<script>`，无需服务器）。

> 如果你在本地用 `python -m http.server` 预览，请在浏览器按 **Ctrl+F5** 强制刷新，
> 否则可能读到旧缓存（`tools/serve.py` 之类的禁缓存服务器可避免此问题）。

## 功能

### ① 参赛名单
- 单打 / 双打切换；单打 1 名球员，双打 2 名（可在一格里填 `姓名A/姓名B` 自动拆分）
- 种子序（1 最高）、**排名**（你给定的先后）、档位（1 最高档）、组合积分（仅数据字段）、备注
- 一键生成示例数据（2–64 人）
- **导出参赛名单**：一键导出为 CSV（列序 `entryName, player1, player2, rank, seedRank, tier, groupPoints, remark`），
  可在 Excel 里可视化编辑后**直接再导入**，实现名单的保存与复用
- **导入** `.csv` / `.txt` / `.xlsx`：自动识别表头（英文与中文表头均可），导入前做完整校验并给出具体错误
- 可下载 CSV 模板（列序与导出完全一致）

### ② 比赛设置
- 小组数、每组人数、每组出线人数、种子数、档位数
- **按人数自动推荐**（一键采用），也可全部手动覆盖
- 顶部给出实际分组人数（如 `3/3/3/3/4/4`）与不整除提示
- 开发者「签名」输入框：填入同一签名必得同一结果（可复现，见下）

### ③ 小组抽签
- **隐式合规生成 + 显式动画回放**两阶段：
  - 先一次性生成完整合规签表；冲突时返回**具体原因**（如“档位 1 的单元过多：第 1 层只有 6 个位置，但已声明 7 个”），**绝不放宽规则**
  - 再按“逐档 / 逐签位”回放抽取动画，**动画落点与预生成结果完全一致，动画中不重新随机**
- 支持**跳过动画**、**重新播放**、**整体重抽**（重抽 = 重新生成 + 重新回放，不在旧结果上局部替换）
- 左侧实时显示进度、当前抽取者与落位、逐条抽取记录

### ④ 淘汰赛签表
- 树状推进（1/8 → 1/4 → 半决赛 → 决赛），A4 横向比例
- 每场保留**场次号**，**时间 / 球台**留空占位
- 轮空位显式标注「轮空」，并注明「某某 晋级」
- 双打单元格显示「姓名A / 姓名B」
- 含**三四名决赛**与**冠军栏**

### ⑤ 导出
| 格式 | 说明 |
|---|---|
| **小组赛签表** | 第 ③ 步「导出小组赛签表」：A4 横向、各小组等宽平铺、**各档次横向对齐**，可导出 PNG / PDF。「出线」栏**留空待勾选**，由你判定，程序不预填晋级 |
| **PDF** | 走浏览器原生打印，**文字为矢量字形**，中文不会乱码；打印对话框里选「另存为 PDF」、纸张 **A4 横向**、勾选「背景图形」 |
| **PNG** | 签表 SVG 栅格化，可选 **2× / 3× / 4×**（3× ≈ 5052×3570 px） |
| **Excel** | 原生 OOXML，**4 张工作表**：选手名单 / 小组分组 / 淘汰赛签表 / 场次清单 |
| **JSON** | 稳定 schema（`schemaVersion: "1.0.0"`），便于接入比赛统计系统 |
| **CSV** | 名单 + 小组 + 签位，便于再导入或交给其他系统 |

## 规则（默认方案）

### 小组赛
1. **人数分配**：组间人数差最多 1 人；多出的人优先放在**靠后**的小组，并明确提示。
2. **种子落位**：前 `seedCount` 个种子按**蛇形**分布到各组 1 号位；种子数多于小组数时，
   第 `g+1` 个及以后的种子按蛇形进入第 2 层（跨 1–2 档）；**高序种子优先占据靠前小组**。
3. **逐档抽签**：非种子按**档位从高到低**逐档抽入小组空位（档带内随机，可复现）。
4. **同档回避**：同一档的单元不在同一组。第 `j` 层的容量 = 人数 ≥ `j` 的小组数，
   因此 `3/3/3/3/4/4` 时第 4 层只有 2 个位置——这是人数不齐的**必然结果**，会提示而非报错。
5. **高排名不过早相遇**：小组赛靠种子分散 + 同档回避；淘汰赛靠同组半区回避。
6. **未填档位**：按实力顺序（种子序 → 组合积分 → 档位 → 姓名）自动填满各层剩余容量，并提示。
7. **约束接口**：`constraints` 数组预留同单位回避等扩展（默认不启用，需求已说明无同单位问题）。

### 淘汰赛（真抽签，不是直接生成）
1. **出线来源**：**只使用你在第 ③ 步标定的「出线名次」**——每组每名选手可指定
   「第 1 出线 / 第 2 出线 …」，同一组内每个名次只能有一人（重复选择会自动互换）。
   没标齐时拦截并列出「A 组 已标 第1（需第 1–2 各 1 人）」，可一键「按名次自动补齐」。
2. **抽签顺序**：`出线名次` 优先（小组第 1 出线 → 第 2 出线 …），
   同一名次内按 **赛前种子排名**（seedRank 升序，无种子序者靠后），再按录入排名、小组序。
   队列把整条顺序**提前列出**；轮到某人时卡片展开，注明「X 组第 N 出线 / 赛前种子第 M / 第 K 位落位」。
3. **落位规则（ITTF 惯例，保留随机性又保证强弱均匀）**：
   - 第 1 位 → 固定 **1 号位（上半区顶部）**
   - 第 2 位 → 固定 **N 号位（下半区底部）**
   - 第 3–4 位 → 在**两个 1/4 区锚点**（N/2、N/2+1）之间随机
   - 第 5–8 位 → 在**四个 1/8 区锚点**之间随机
   - 第 9–16 位 → 在剩余锚点之间随机
   锚点由 `anchorList(N)` 递归生成，档带由 `seedBand(位次)` 给出。
4. **轮空**：由前 `byeCount` 个锚点的**对手位**一次性确定，因此天然按 1/4 区均匀铺开，
   且 **绝不出现「轮空 vs 轮空」**；实体上等价于“头号种子首轮轮空”。
5. **同组半区回避（硬约束）**：同一小组的两名出线者不得落在同一半区。
   落位时实时维护上/下半区容量，先把需求与可用位置对齐再逐人放，避免后期无解。
   同组尽量分散到不同 1/4 区（软约束，优先但不强制）。
6. **两阶段 + 动画**：先一次性算出完整合规签表，再逐位回放——
   左侧点卡片抽取，右侧 16 个签位盘中**逐个遍历该位的全部合法候选**后落定；
   支持「全部放入」「从头重播」「整体重抽」。动画只做表现，不改变已生成结果。
7. **三四名决赛**：两场半决赛负者对决，场次号接续在最后。
8. **约束冲突**：一律返回具体原因（如“同组半区回避无法满足：需要上半区 x 个（可用 y）”），绝不放宽。

### 可复现（固定随机种子）
- 界面「签名」框：填写任意文本（如 `2026-final`），**同一签名 → 同一结果**。
- URL 参数：`index.html?seed=2026-final`（开发者/复盘用，不在主界面强调）。
- 重抽：签名留空时用新随机种子；填写签名时在其上派生 `#N`，保证“重抽 = 重新生成”。
- 清空本地存档：`index.html?reset=1`（开发者用）。

```js
// entry（参赛单元，抽签对象）
{ id, players: ['姓名'|'姓名A','姓名B'], seedRank, tier, groupPoints, remark }
```

导出 JSON（稳定接口）：

```
{
  schema: 'table-tennis-draw',
  schemaVersion: '1.0.0',
  generatedAt, generator,
  event:  { type, groupCount, groupSize, qualifiersPerGroup, seedCount, tierCount, randomSeed },
  entries: [{ id, name, players[], seedRank, tier, groupPoints, remark, order }],
  groups:  [{ index, label, size, members: [{ slot, entryId, name, seedRank, tier }] }],
  knockout:{ size, rounds: [{ round, name, matches: [{ no, slotA, slotB, entryA, entryB, nameA, nameB, bye, winnerTo }] }],
             thirdPlace, qualifiers: [{ entryId, name, groupIndex, groupLabel, rank, label, slot }] },
  notices: []
}
```

## 与需求的差异（重要）

| 需求原文 | 本实现 | 原因 |
|---|---|---|
| PDF 用 **pdfmake** 生成、嵌入思源黑体 | **浏览器原生打印**输出 PDF（矢量文字） | pdfmake 需 ~2.5MB 库 + 数 MB CJK 字体；本实现保持**零依赖、离线可用、无 CDN**。原生打印同样是矢量（中文不乱码），效果等价且体积小几个数量级 |
| 图片用 **html2canvas** | **SVG → Canvas** 原生栅格化 | 我们的签表本身就是 SVG，直接栅格化比 html2canvas 更清晰（不受 DOM 渲染差异影响），且可指定 2×/3×/4× |
| Excel 用 **SheetJS** | 原生 OOXML 生成（自写 ZIP） | 避免 900KB+ 依赖；产物是标准 .xlsx，Excel/WPS/Numbers 均可打开 |
| 树状线框用 SVG 生成后嵌入 | 签表**整体就是 SVG** | 更彻底：线框、文字、色块皆为矢量，PDF/PNG 都直接来自同一份 SVG |

如果必须坚持 pdfmake/html2canvas/SheetJS，可以在此基础上替换 `js/export.js` 的
对应函数——签表已是 SVG、数据已是稳定 JSON，接库很直接。

## 浏览器要求

- Chrome / Edge / Firefox / Safari 现代版本
- ×.xlsx **导入**需要 `DecompressionStream`（Chrome 80+/Edge 80+/Safari 16.4+）；
  不支持时会提示改用 CSV（导出 xlsx 不需要该特性）
- 大签表（64 人）导出 4× PNG 约 6700×4700 px，低配机器可能偏慢，可用 2×/3×
