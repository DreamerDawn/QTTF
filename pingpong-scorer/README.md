# 乒乓球计分器（Table Tennis Scorer）

纯静态的乒乓球比赛计分器：单打 / 双打、BO3/BO5/BO7 与固定 K 局、加球、暂停与医疗暂停、
逐球统计与单局比分走势图（SVG 自绘）。

**无后端、无构建步骤、不依赖任何外部 CDN 或第三方库**。全部文件为静态资源，
可直接放进 GitHub Pages 仓库根目录或 `docs/` 目录运行。

---

## 部署到 GitHub Pages

### 方案 A：仓库根目录
把本目录的 `index.html`、`css/`、`js/` 复制到仓库根目录，然后在仓库
**Settings → Pages → Build and deployment** 中选择分支 `main`、目录 `/ (root)`。

### 方案 B：docs 目录（推荐）
把 `index.html`、`css/`、`js/` 复制到仓库的 `docs/` 下，然后在 Pages 设置中选择
分支 `main`、目录 `/docs`。

访问 `https://<用户名>.github.io/<仓库名>/` 即可使用。`tests/` 目录不参与页面运行，
可以不放上去（放上去也不影响）。

### 本地打开
直接双击 `index.html` 即可（全部用经典 `<script>` 标签、相对路径，无需服务器）。

### 内置自测
- 浏览器：打开 `index.html?selftest=1`，页面底部会显示验收用例 1–12 与回归用例的自测面板
  （逻辑 + DOM/交互共 35 项）。
- Node：`node tests/selftest.js`（跑逻辑层 22 项，DOM 部分标记为跳过）。

## 关键默认规则（含歧义处的取舍）

| # | 项目 | 本实现采用的定义 |
|---|---|---|
| 1 | 固定 K 局是否提前结束 | **打满 K 局**（即使胜局已锁定），按胜局多者获胜；K 为偶数且胜局相同判平局；**不显示赛点** |
| 2 | 加球起算点 | 以目标分 T：开启加球时，该局第 **2(T-1)** 球之后进入“需领先 2 分”，此阶段每 **1 分**换发；此前每 2 分换发。T=1 时先到 1 分胜 |
| 3 | 双打顺序模型 | 4 人固定循环 `[先发球员 → 首先接发球员 → 先发球员搭档 → 接发球员搭档]`，如 A1 先发、B1 先接则为 `A1→B1→A2→B2`；普通阶段每人连发 2 球，加球阶段每人 1 球并**沿同一循环继续**（不重置） |
| 4 | 下一局发球 | 由上一局**接发球队先发**；该队先发球员 = 上一局该队首先接发球员 |
| 5 | 死球与暂停时机 | 死球 = 每球判定后至下一球记录前。普通暂停**只能在死球状态**请求（局间、本局 0:0 首球前均不可）；医疗暂停不限时机，局间请求记入刚结束那一局 |
| 6 | 局点 / 赛点计数 N | N = 该方拿到过的第几个“机会”（有多少个来球能让他赢下本局/本场），**分方独立计数**。对方每救掉一个，下一个来球就是该方的再下一个：10:7 第 1 个 → 10:8 第 2 个 → 10:9 第 3 个。被追平（10:10）后状态消失、停止累加，之后重新出现（11:10）则从第 1 个重新开始。若全程未出现“再 1 分即胜”（如 11:5）则为 0 |
| 7 | 换边提示 | 仅 **BO 赛制的决胜局**适用，任一方先到 **⌈T/2⌉** 时提示一次；固定 K 局不提示；换边**不自动切换左右**，只提示 + 提供“手动换边”（仅切换显示，不影响数据） |
| 8 | 撤销范围 | 只回退逐球记录；比分、发球方/发球人、局点/赛点、局分、统计、图表、局与场的结束状态全部随之回退。**暂停记录与已用暂停次数不因撤销回退**（只有“重置比赛”恢复） |
| 9 | 单局时长口径 | 该局开始 → 结束的墙钟时长，**包含**该局内普通/医疗暂停，**不含**局间。进行中的当前局显示为「局开始 → 此刻」的实时值（不冻结） |
| 10 | 总比赛时长 | “开始比赛” → 比赛结束，**包含**局间与所有暂停 |
| 11 | 重置本局 | 仅对当前局可用（比赛结束后禁用）；清除该局比分与本局事件、单局计时重置、发球方恢复该局开始发球方；**不返还**已用普通暂停次数 |
| 12 | **Greatest lead against** | 保留名称，定义为“**单局胜方在该局中曾建立的最大领先分差**”；未领先记 0；**负方记 0**；全场取各局胜方该值的最大值 |
| 13 | Greatest deficit overcome | 仅单局胜方：该局曾落后的最大分差且最终获胜；未落后记 0；负方记 0 |
| 14 | 全场最大值类指标 | Biggest lead / Most consecutive won / Most consecutive lost 全场均取**各局单局最大值中的最大值**，不跨局累计、不按全场总得分差计算 |
| 15 | 导出 CSV 结构 | 单个 CSV（带 UTF-8 BOM，便于 Excel 打开），含 `SECTION,POINTS` 逐球表、`SECTION,GAMES` 每局汇总表、`SECTION,STATS` 统计表三段 |
| 16 | 本地存储 | `localStorage` 仅保存**当前一场**比赛，不提供历史比赛列表 |
| 17 | **局间休息** | 每局结束后显示 **1 分钟倒计时**（自上一局结束时刻起算）。局间**不锁定计分**，倒计时到 0 仅提示、随时可开始下一局；局间**不计入任何一局的单局时长**，但**计入总时长** |
| 18 | 选手姓名编辑 | 姓名框可**完全清空重输**，编辑期间不清除前后空格；空名在界面与导出中回退为默认名（选手A/选手B、A1…B2），**比赛开始**时由 `normalizeConfig` 统一 trim 并补默认名 |
| 19 | 倒计时显示 | 普通暂停倒计时与局间倒计时均以**大号数字**（桌面 52px、窄屏 34–40px）显示，约为说明文字的 3.5 倍 |

以上 1–19 条同时写在页面底部的“规则说明”中。

## 快捷键

| 按键 | 功能 |
|---|---|
| `A` 或 `←` | A 方加 1 分 |
| `B` 或 `→` | B 方加 1 分 |
| `Ctrl+Z`（或 `⌘Z`） | 撤销上一球 |
| `P` | 请求普通暂停（弹窗选择方） |
| `M` | 请求医疗暂停（弹窗选择方） |

## 实现要点

- **唯一真源**：`state.points`（逐球记录）+ `state.gameStarts`（各局开始时间）+ `state.pauses`（暂停记录）。
  比分、胜局、局点/赛点、发球方/发球人、局分、统计、图表全部由 `engine.derive()` 重放得出，
  因此“撤销 = 弹出末球”“重置 = 清空子集”“刷新 = 反序列化”三者天然一致。
- **发球引擎**：单打 `p = ⌊n/2⌋ mod 2`，双打 `p = ⌊n/2⌋ mod 4`；加球阶段改为每人 1 球
  （`p = (T-1) + (n-1-phaseBase)`），两段公式在交界处连续，故加球只是“继续轮转”。
  每局首发由 `config + 局号` 递归推导（`order_{g+1} = [order_g[1], order_g[0], 搭档…]`），
  无隐藏状态，撤销 / 刷新天然一致。
- **计时**：用绝对时间戳（epoch ms）保存，渲染时按墙钟计算并每 250ms 刷新；
  刷新页面后按 `now - start` 续算，暂停期间不冻结任何计时。
- **图表**：`document.createElementNS` 自绘 SVG（网格 / 坐标轴 / 目标分参考线 / 图例 / 数据点），
  每张图含球序号 0 的 0:0 起点。
- **防连加**：加/减分只绑定 `click`（长按不产生重复 click，天然“一次点击只加 1 分”），
  按钮为移动端大尺寸（加分按钮高 96px）并禁用长按选中/高亮。

## 已知取舍

- 固定 K 局不自动提示换边（按规格），如需可为任意局手动换边。
- 撤销不回退暂停记录与已用暂停次数（按规格，只有重置比赛恢复）。
- localStorage 只保留当前一场比赛，没有历史比赛列表（按规格）。
